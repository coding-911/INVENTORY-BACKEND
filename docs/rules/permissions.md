# 권한 매트릭스

> 원본(노션): https://app.notion.com/p/40ea7b147db34b08b8bdfff1001cc500  
> 내보낸 날짜: 2026-11-24. **노션이 원본이다.** 이 파일과 노션이 다르면 노션을 따른다.

> 🔐 누가 어떤 API를 호출할 수 있는지와, 같은 API 안에서 역할에 따라 달라지는 규칙을 모았다 (2026-11-24). API별 원본은 [API 목록](https://app.notion.com/p/421b82ca31e581898e3fe58ea8d40ecb)의 "권한" 칸이고, 인증 방식은 [API 명세서](https://app.notion.com/p/408b82ca31e580d19b7ee382dacd572b) 1.3절이다. 둘이 다르면 API 목록 행을 고치고 이 페이지를 다시 맞춘다.

> 🎨 이 페이지는 전부 요구사항 정의서 v1.1 이후 새로 작성한 내용이다.

## 1. 권한 체계

| 구분 | 값 | 뜻 |
|---|---|---|
| 역할 (하나) | `ADMIN` 관리자 | 입력자의 일 + 승인·확인, 잔량 마감, 월 마감, 기준 정보 관리, 계정·권한 관리, 7일보다 지난 날짜 입력 |
|  | `OPERATOR` 입력자 | 입고·출고·배정·납품 같은 일상 처리, 거래 문서·거래처·제품 등록 |
|  | `VIEWER` 조회자 | 보기만 한다 |
| 금액 권한 (역할과 따로, 0~2개) | `COST_VIEW` 금액 보기 | 단가·원가·마진·부대비용·대여료가 응답에 들어간다. 없으면 필드 자체가 빠진다(INV-83) |
|  | `COST_EDIT` 금액 수정 | 단가·부대비용·대여료를 넣고 고친다. 금액 보기를 포함한다 |

- 역할과 금액 권한은 access token(JWT)에 들어 있고, 서버가 요청마다 검사한다. 화면에서 숨기는 것은 편의일 뿐이다.
- 역할·금액 권한·사용 여부가 바뀌면 그 사람의 기존 토큰은 바로 무효가 된다(`tokens_valid_after`, INV-80).
- 비밀번호 변경이 필요한 사용자(새 계정·초기화 직후)는 내 정보·본인 비밀번호 변경·로그아웃만 쓸 수 있다. 나머지는 403 `PASSWORD_CHANGE_REQUIRED` (API 명세서 1.14, #100).
- 권한이 없으면 403 `FORBIDDEN`, 로그인하지 않았으면 401 `UNAUTHENTICATED`.

### 1.1 이 페이지의 조건 표기

| 표기 | 뜻 | Spring Security 예 |
|---|---|---|
| **모두** | 로그인한 사용자 누구나 (관리자·입력자·조회자) | `authenticated()` |
| **입력** | 관리자 또는 입력자 | `hasAnyRole('ADMIN','OPERATOR')` |
| **관리자** | 관리자만 | `hasRole('ADMIN')` |
| **금액보기** | 역할과 상관없이 금액 보기(또는 금액 수정) 권한이 있음 | `hasAnyAuthority('COST_VIEW','COST_EDIT')` |
| **금액수정** | 금액 수정 권한이 있음. 조회자는 이 권한을 가질 수 없다(2절, INV-87) | `hasAuthority('COST_EDIT')` |
| A **그리고** B / A **또는** B | 둘 다 / 둘 중 하나 |  |

> ⚠️ API 목록의 "권한" 칸은 여러 값을 나열만 해서 "또는"인지 "그리고"인지 드러나지 않는다. 예: 첨부 열기 [관리자, 금액 보기]는 **또는**, 초기 재고 단가 [관리자, 금액 수정]은 **그리고**(INV-74). 구현은 이 페이지의 조건을 따른다.

## 2. 기본 규칙과 확정 전

| API 종류 | 기본 조건 |
|---|---|
| 조회(GET) | 모두 |
| 등록·수정·삭제·업무 동작 | 입력 |
| 금액 조회 (cost 모듈 GET) | 금액보기 |
| 금액 넣기·고치기 (cost 모듈 쓰기) | 금액수정 |
| 본인 관련(내 정보, 본인 비밀번호, 내 알림, 로그인·로그아웃) | 모두 |

151개 API 중 기본 규칙과 다른 것은 3절에 모두 적었다. 3절에 없는 API는 위 기본 조건을 따른다.

**조회자에게는 금액 수정 권한을 주지 못한다** (2026-11-24 확정, #105, INV-87). 금액 보기는 줄 수 있다. 계정 만들기·수정에서 조회자 + 금액 수정 조합이면 400 `USER_VIEWER_COST_EDIT`. 금액 수정이 있는 사람을 조회자로 바꿀 때도 같은 오류다(금액 수정을 함께 빼고 보내야 한다). 그래서 금액 쓰기 API의 "금액수정"은 사실상 입력 **그리고** 금액수정이다. 서비스에서도 한 번 더 확인한다.

### 3.2 조회지만 조회자는 못 함 (입력)

| 단계 | API | 메서드·경로 | 이유 |
|---|---|---|---|
| 2 | 승인·확인 대기함 목록, 요청 하나 | `GET /api/v1/admin/review`, `/review/{id}` | 입력자는 자기가 낸 요청만, 관리자는 전부 본다 |
| 3 | 삭제 목록 | `GET /api/v1/trash` | 기준 정보·첨부 외 항목. 기준 정보의 삭제 목록과 복구는 관리자만(1.9) |

### 3.3 금액 권한으로 막는 API

| API | 메서드·경로 | 조건 |
|---|---|---|
| 금액 변경 이력, 부대비용 목록·하나, 프로젝트 금액·마진, 창고 재고 평가액 | `GET /api/v1/cost/change`, `/cost/extra-cost…`, `/cost/project/{projectId}/margin`, `/cost/stock-valuation` | 금액보기 |
| 부대비용 넣기·고치기·삭제, 거래 문서 품목 단가, 대여료 | `POST·PATCH·DELETE /api/v1/cost/extra-cost…`, `PATCH /cost/trade-document/{id}/line-price`, `/cost/loan-fee/{loanDocumentId}` | 금액수정 |
| 초기 재고 단가 | `PATCH /api/v1/cost/opening-cost` | 관리자 **그리고** 금액수정 (INV-74) |
| 첨부 파일 열기·내려받기 | `GET /api/v1/importing/attachment/{id}/content` | 관리자 **또는** 금액보기 (INV-86) |
| 통화 목록 | `GET /api/v1/cost/currency` | 모두 (금액이 아닌 코드 표) |

### 3.4 응답에 금액 필드가 섞이는 API

호출은 기본 조건(모두)이고, 금액보기가 없으면 금액 필드를 빼고 응답한다(INV-83, 개발 컨벤션 3절). 거래 문서 목록, 거래 문서 하나, 대차 문서 하나(대여료).

## 4. 같은 API 안에서 역할에 따라 달라지는 규칙

API를 호출할 수는 있지만 내용에 따라 관리자만 되는 경우다. 서비스에서 검사하고, 막히면 403 `FORBIDDEN` 또는 표의 오류 코드로 돌려준다.

| 대상 API | 규칙 | 근거 |
|---|---|---|
| 업무 날짜가 있는 모든 업무 동작 | 입력자는 오늘부터 7일 전까지만, 관리자는 마감되지 않은 달이면 됨. 미래 날짜는 둘 다 안 됨 | INV-15·16, `BUSINESS_DATE_TOO_OLD` |
| 제품 수정 | 이력 있는 제품의 Item Code 변경은 관리자만, 사유 필수 | INV-72 |
| 거래처·제품·담당자 삭제 | 입력자도 지울 수 있지만, 삭제 목록에서 되살리는 것은 관리자만 | 1.9 |
| 거래 문서 수정 | 다른 프로젝트로 옮기기와 기준일 이전 처리 수량 입력(첫 마감 전)은 관리자만 | INV-55, 가이드 "프로젝트 만들기" |
| 장비 시리얼·메모 수정 | 고객에게 납품한 적 있는 장비의 시리얼은 관리자만. 입력자가 고치면 같은 트랜잭션에서 사후 확인 요청이 생긴다 | INV-61·77, #59 |
| 발주 없이 입고, 대차 기한 바꾸기 | 입력자도 하지만 관리자 사후 확인 요청이 함께 생긴다 | INV-77, #9·#72 |
| 폐기 요청, 대여 출고, 동급 모델 정산, 실사 제출(차이 있음) | 입력자가 요청하고 관리자가 승인해야 원장·장비가 바뀐다 | INV-41·62 |
| 실사 중 범위의 일반 처리 | 막힌다. 관리자만 예외로 처리할 수 있고, 그 제품은 재실사 대상이 된다 | INV-48 |
| 완료된 거래 문서 | 메모는 입력, 금액은 금액수정만 바꾼다 | INV-67 |
| 계정 수정·삭제 | 관리자는 자기 역할·사용 여부를 바꾸거나 자기를 지울 수 없고, 사용 중인 관리자는 한 명 이상 남아야 한다 | INV-80, `USER_SELF_CHANGE`·`USER_LAST_ADMIN` |
| 삭제 목록·복구 | 첨부(`ATTACHMENT`)는 입력, 부대비용(`EXTRA_COST`)은 금액보기가 있어야 목록에 보임 | 삭제 목록 API 행 |

## 6. 테스트

- API마다 "허용 역할로 성공", "허용되지 않은 역할로 403" 테스트를 하나씩 둔다. 이 페이지 3절의 API는 경계 조합(예: 조회자+금액 보기, 입력자+금액 수정)까지 넣는다.
- 금액 필드 테스트: 금액보기 없이 3.4절 API를 부르면 JSON에 금액 키가 없어야 한다(INV-83).
